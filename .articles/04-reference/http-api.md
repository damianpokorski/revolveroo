The API is served under `/api` on the same origin as the web UI. The settings UI is its main client, and an OpenAPI description is generated by the server.

:::caution
The API has no authentication. Anyone who can reach Revolveroo can read and change its configuration. See the [security model](/revolveroo-draft/reference/security/).
:::

## Health

`GET /api/health` returns the app's status. The Docker `HEALTHCHECK` and the CI smoke test both use it.

```bash
curl http://localhost/api/health
```

```json
{ "status": "ok", "proxyEnabled": false }
```

| Field          | Meaning                            |
| -------------- | ---------------------------------- |
| `status`       | `"ok"` when the server is up.      |
| `proxyEnabled` | `true` when `PROXY_DOMAIN` is set. |

## Resources

The main resources are `/api/tabs`, `/api/windows`, `/api/displays` and `/api/config`, plus a read-only overview feed. They mirror the sections of the [data file](/revolveroo-draft/reference/data-file-schema/).

## Cross-origin requests

In production the API sends no CORS headers, because the web UI is served from the same origin. State-changing requests (`POST`, `PUT`, `PATCH`, `DELETE`) that a browser reports as coming from another site or origin are refused with `403`. Scripts and `curl` send no `Origin` header and are unaffected.
